# СМ-Клиника, Санкт-Петербург: прототип парсера НаПоправку

Проверена живая страница филиала на Дыбенко 05.10.2026: карточки врачей, специальности, адреса, цены и кнопка «Показать ещё». В показанных карточках запись только по телефону. Это прототип справочника врачей, НЕ готовый парсер ближайших слотов со всех трёх агрегаторов.

## Запуск в Windows (Python 3.11+)

Откройте терминал в распакованной папке:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python parser.py --visible
```

Выход: отдельный CSV с разделителем `;` для каждого запуска, история в `output/history.sqlite`, отчёт о полноте/ошибках в JSON. Для Power BI: «Получить данные → Папка», выбрать output и отфильтровать расширение .csv. Частичные запуски отмечены `partial` в отчёте: не использовать их для оценки изменения числа врачей.

## Что реализовано

- Сбор одного филиала с догрузкой «Показать ещё»; дополнительные проверенные ссылки филиалов можно добавить в config.json.
- Ограничение адресов Санкт-Петербургом; страницы других городов не принимаются.
- Один врач в разных филиалах остаётся отдельными строками. Все специальности и видимые цены записываются через `;`; цены не привязаны к отдельной услуге и не подходят для сравнения стоимости конкретного приёма.
- История запусков; дедупликация по URL врача и адресу в пределах страницы филиала; ошибки не превращаются в отсутствие слотов.
- Умеренные паузы, остановка при HTTP ошибке/изменении разметки. CAPTCHA и ограничения сайта не обходятся.

## Доступность

`phone_only`: сайт явно сообщает запись только по телефону.
` schedule_not_extracted` (без начального пробела): карточка получена, но адаптер расписания ещё не реализован.
`nearest_slot` и `days_to_slot` пока всегда пустые. Пустое значение НЕ означает 0 дней или отсутствие свободных мест. Статус `no_slots` намеренно не выставляется без проверенного расписания и горизонта поиска.

## Проверка и ограничения

Селекторы и JavaScript извлечения проверены на живой странице в браузере. Полный локальный запуск Python с Playwright, догрузка всех 119 специалистов, все филиалы, расписание, ПроДокторов и СберЗдоровье пока не проверены/не реализованы. Обычный HTTP запрос из среды разработки вернул 403, браузер страницу открыл. Работоспособность автоматического Chromium на компьютере пользователя ещё нужно проверить.

Для завершения задачи необходим источник опубликованных слотов СМ-Клиники (другой агрегатор или её собственная запись), проверка структуры расписания по филиалу и услуге, затем отдельный адаптер. Официальный партнёрский API сам по себе не гарантирует доступ к расписанию конкурентов.

После успешной ручной проверки запуск можно добавить в Планировщик заданий Windows: программа — полный путь к .venv\Scripts\python.exe; аргумент — полный путь к parser.py; рабочая папка — папка проекта. Автоматический запуск использует браузер без окна, пока отдельно не добавлен --visible. Расписание запуска этим архивом не устанавливается.

## Дополнение: официальный источник слотов СМ-Клиники

На живой форме проверены взрослый профиль с условной датой 01.01.1990, выбор специальности «Кардиолог», карточки пяти врачей с шестью местами приёма, даты в выпадающем списке и время. Нажатия на время и создание записи не выполняются.

Первый запуск:
```powershell
.venv\Scripts\python sm_slots.py --visible
```
Несколько специальностей:
```powershell
.venv\Scripts\python sm_slots.py --visible --specialty Кардиолог --specialty Терапевт
```
Все пункты каталога (включает также диагностику и акции):
```powershell
.venv\Scripts\python sm_slots.py --all-specialties
```

Адаптер раскрывает список дат каждого места приёма, выбирает самые ранние даты в горизонте 60 дней и берёт минимальное будущее время. Каждый филиал/услуга — отдельная строка. `available` означает найденный опубликованный слот; `schedule_unresolved` означает, что подтвердить доступность не удалось. Пустое время не считается отсутствием слотов. `days_to_slot` — разность календарных дат в Москве (сегодня = 0).

CSV и история этого источника находятся в sm_output. Источник обозначен `smclinic_official`; автоматическое объединение с НаПоправку пока не выполняется. `record_key` — ключ наблюдения на основе ФИО/адреса/услуги/специальности, а не подтверждённый идентификатор врача между сайтами. Пример Думчевой показывает, почему нельзя смешивать адреса: на Малой Балканской, 23 и 26 даты отличаются.

Структура извлечения подтверждена в браузере. Полный Python запуск, все страницы/специальности, смена года и отсутствие расписания требуют проверки на компьютере пользователя. Возможна задержка обновления времени после выбора даты: в прототипе используется пауза 1 секунда, для промышленной версии нужен подтверждённый сигнал завершения загрузки. Дата запуска фиксируется по каждой карточке; доступность может изменяться в ходе сбора. Детский профиль пока не реализован. Нельзя использовать этот прототип как гарантированно полную производственную выгрузку.
